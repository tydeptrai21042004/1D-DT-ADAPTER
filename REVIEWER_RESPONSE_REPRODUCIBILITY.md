# Response to Comment 13: Open-source and reproducibility package

We thank the reviewer for this important recommendation. We substantially strengthened the repository and prepared a CNN-only reproducibility release. The revised package provides pinned `requirements.txt`, `requirements-kaggle.txt`, and `environment.yml` files, exact dataset and pretrained-weight instructions, a versioned experiment manifest, committed split files, deterministic split-generation and recording utilities, and table-specific executable scripts.

All stochastic CNN classification experiments are now defined for three independent seeds (0, 1, and 2). Python, NumPy, PyTorch CPU/CUDA, data samplers, data-loader workers, model initialization, augmentation, and generated validation partitions are controlled by the selected seed. The same seed-specific split is shared by all methods within a comparison. The aggregation utility verifies that all required successful seed runs are present and exports raw results and mean ± sample-standard-deviation summaries in CSV, JSON, and LaTeX formats.

We also added runnable **Full fine-tuning** and **Linear probing** reference controls to every cross-method CNN comparison target. Full fine-tuning updates the complete backbone and classifier. Linear probing updates only the task classifier and freezes both backbone parameters and BatchNorm running statistics. Both controls use the same dataset, backbone, pretrained weights, split, augmentation, optimizer family, epoch count, batch size, and seed as DT1D-Adapter and the other baselines.

A single manifest, `configs/paper/cnn_three_seed_manifest.yaml`, maps manuscript Tables 2–15 and 18–19 and result-driven Figures 1 and 4 to exact datasets, CNN backbones, protocols, methods, and seeds. It generates 408 portable per-run YAML configurations. Each table and figure has a direct shell entry point, and the package includes a configurable Kaggle `%%bash` cell. Figures 2 and 3 are deterministic mathematical/architecture illustrations and therefore do not require random training seeds. Transformer/ViT experiments are outside the scope of this release and are rejected by the paper runner.

For datasets without an official train/validation/test partition, we strengthened model-selection validity. In particular, Caltech101 and EuroSAT now use disjoint 80% training, 10% validation, and 10% test subsets. The three committed Caltech101 split manifests contain 6,942 training, 868 validation, and 867 test examples for each seed. All affected manuscript values must therefore be regenerated rather than copied from the previous single-holdout results.

Every configuration-driven run records the resolved YAML, exact executable command, independent seed, split manifest, source branch and commit, dirty status, Python/package/CUDA/cuDNN/GPU/driver environment, resolved torchvision pretrained-weight enum and URL, stdout log, run status, epoch history, checkpoints, test metrics, efficiency metrics, and checksums. The repository also includes `CITATION.cff`, CodeMeta and Zenodo metadata, a changelog, release validation, annotated-tag creation, deterministic archive generation, and GitHub-release scripts.

To resolve naming inconsistencies, **DT1D-Adapter** is the canonical name. New experiments use `models/dt1d_adapter.py`, class `DT1DAdapter`, `--tuning_method dt`, and `--dt_*` arguments. The legacy `models/hcc_adapter.py` file is retained only as a documented import shim for old checkpoints and is not used as the canonical implementation.

Before packaging, we validated all 136 unique CNN target/method/variant model constructions, executed real CPU FakeData smoke runs for all 13 supported method presets, and ran the complete automated test suite (**293 passed, 1 CUDA-only test skipped, and 10 parameterized subtests passed**). We also documented one historical inconsistency rather than concealing it: the Table 9 DT1D-Adapter trainable-parameter value in the current manuscript does not match the canonical ResNet-50 implementation and must be replaced by the regenerated three-seed result.

The prepared source version is `v0.8.0` on branch `dt1d-v8-cnn-three-seed`. Remote tag creation, the complete real-dataset GPU execution, GitHub release publication, and Zenodo DOI assignment remain repository-owner release steps because they require the owner's credentials and target hardware.
